# Своя игра · Корпорация Пирожкова

**[Открыть приложение](https://fliin.github.io/svoya-igra-rnimu/)** · [Репозиторий](https://github.com/Fliin/svoya-igra-rnimu)

Статическое приложение для командного вечера: HTML, CSS и JavaScript, без сервера приложения, учётных записей и сборки. Подготовлено для GitHub Pages.

## Запуск на компьютере

Нужен Node.js 22 или новее. В папке проекта выполните `npm start`, затем откройте [приложение](http://127.0.0.1:4173). Установка зависимостей не нужна. Для проверки игровой логики: `npm test`.

Папку `public` можно разместить на любом статическом хостинге. Открывать `index.html` двойным щелчком не следует: браузеры ограничивают загрузку JavaScript-модулей через `file://`.

## Как подготовить вечер

1. В «Банке вопросов» создайте темы и вопросы. У каждого вопроса и ответа можно задать текст, полный URL изображения либо оба поля. Там же редактируются коты и модификаторы.
2. В «Настройке игры» задайте от 1 до 3 команд. Добавьте раунды, пять цен и до шести тем в каждый раунд. Кнопка клетки открывает редактор: вручную выберите вопрос из банка или создайте локальный вопрос только для этой клетки.
3. Отметьте нужные специальные клетки и выберите общие пулы котов и модификаторов. Снаружи клетки выглядят одинаково. Один вопрос нельзя назначить в разные клетки; темы могут повторяться между раундами.
4. Исправьте ошибки проверки готовности. Репетиция доступна и для неполного поля: отсутствующий вопрос получит поясняющую заглушку только в репетиции.
5. Запустите игру и при необходимости включите «На весь экран». Переключение раундов свободное. Вопрос и ответ занимают отдельный экран с постоянным табло внизу.

Первое открытие загружает **демонстрационный набор**: 6 тем × 5 вопросов, 3 кота, 3 модификатора. Личные вопросы и фотографии в проект не включены.

## Как вести игру

Откройте клетку. При специальном событии сначала появится его отдельный экран. Для кота назначьте стоимость и команду, которая отвечает первой. Кот заменяет обычный вопрос, а его текст выбирается из пула без повторений. Модификаторы выбираются случайно с возможностью повторения; кот и модификатор могут выпасть вместе.

Команды отвечают устно. Выберите отвечающую команду; при ошибке нажмите «Ошибка · разрешить перехват», затем назначьте другую. Это отмечает попытку, но пока не меняет счёт. После «Показать ответ» доступны отдельные «+» и «−» у каждой команды. Каждое нажатие — самостоятельная операция; количество нажатий не ограничено. Ведущий сам распределяет начисления и списания, включая ошибки при перехватах. Таймера нет.

Множитель действует на начисление и списание. Фиксированное число **прибавляется** к операции при условии «начисление», «списание» или «каждая операция». Пример: при цене 300 фиксированный эффект +100 на списание даёт −200. Отрицательное значение усиливает штраф. Результат округляется до целого. Под каждой командой отображаются фактические суммы операций.

Нажатие на табло открывает ручную установку счёта без модификатора. Отрицательные очки разрешены. История сохраняет все изменения. После завершения вопроса клетка блокируется; ручная корректировка её не восстанавливает. Можно закрыть вопрос без баллов. Игра завершается вручную, результаты учитывают и ничью.

## Сохранение и репетиция

Одна текущая игра автоматически сохраняется в `localStorage`: банк, назначенные копии вопросов, пулы, счёт, сыгранные клетки, активный вопрос, выбранный спецэффект и история. Для редакторов сохранение происходит по кнопке «Сохранить», для обычных настроек — при изменении поля. При возврате после обновления нажмите «Продолжить игру».

Репетиция создаёт отдельную временную копию с нулевым пробным прогрессом. Она не записывается в настоящее сохранение. Выход или обновление страницы отбрасывает пробные изменения. Настоящая игра остаётся на прежнем месте, включая незавершённый вопрос. При изменении игры в другой вкладке запись блокируется до обновления страницы, чтобы избежать потери прогресса.

Вопросы в клетках — копии банка. Редактирование банка не изменяет подготовленные клетки. После старта можно отдельно менять неоткрытые клетки; открытые и сыгранные защищены. Специальные пулы фиксируются при старте, поэтому редактирование банка не меняет уже начатую игру.

«Сбросить прогресс» после обычного окна подтверждения обнуляет счёт и сыгранные клетки, сохраняя поле и банк. «Новая пустая игра» заменяет поле, сохраняя банк. Импорт и экспорт не входят в эту версию согласно предложенному в итоговой спецификации объёму MVP.

Данные привязаны к браузеру и адресу сайта, не синхронизируются между устройствами. Очистка данных сайта удалит их. Изображения по URL требуют доступности внешнего сервера; ошибка загрузки показывается на экране. При подготовке используйте прямые ссылки на картинки. Шрифт загружается с Google Fonts; без него используется системный. Исходники и демонстрационные вопросы публичного репозитория не содержат сохранений из браузера.

## Публикация на GitHub Pages

В проект включён `.github/workflows/pages.yml`: тестирование на Node.js 22, загрузка `public`, публикация в среду `github-pages`. Все ссылки относительные, поэтому приложение работает по адресу проекта `https://USER.github.io/REPO/`.

Если установлен и авторизован GitHub CLI (`gh auth login`), из папки проекта можно запустить:

```powershell
.\scripts\publish.ps1
```

Скрипт создаст новый публичный репозиторий `svoya-igra-rnimu`, включит Pages с источником GitHub Actions, отправит код, дождётся workflow и проверит HTTP-ответ опубликованного сайта. При конфликте существующего репозитория или отсутствии прав он остановится с ошибкой. Секреты в проект не записываются.

Можно опубликовать вручную: создать репозиторий, отправить проект в `main`, в **Settings → Pages → Source** выбрать **GitHub Actions** и запустить workflow. Проверить зелёный workflow и адрес из **Deployments → github-pages**. Наличие workflow-файла само по себе не подтверждает публикацию.
